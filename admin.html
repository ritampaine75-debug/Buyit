With public database rules, anyone who can reach your database can read or reset this stored hash. This gate protects against casual access only. Real security requires locked-down rules + Firebase Auth or a server-side admin — see the hardening checklist below.
Min 8 characters. Stored as a salted SHA-256 hash at settings/admin/passwordHash.

Production hardening checklist

① Replace public DB rules with scoped rules: products/settings readable, orders writable only by matching device, payment credentials never readable.
② Move the PayZapi key to a server proxy (Proxy URL mode) and delete it from the database.
③ Configure the PayZapi webhook (HMAC-SHA256) to fulfill orders server-side, eliminating client trust entirely.
④ Enable Firebase Auth for admin, or gate the admin page behind your host's access control.
⑤ Rotate the PayZapi key now if it has ever been stored in a public DB.
